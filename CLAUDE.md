# Qazaq Trainer — тренажёр для QRT и ҚАЗТЕСТ

Сайт-тренажёр для подготовки к государственным экзаменам по казахскому языку.
Один пользователь, без бэкенда. Все решения ниже зафиксированы — не переспрашивать.

## Стек
- Чистый HTML/CSS/JS, без фреймворков и без node (на машине его нет).
- Исходники в `src/`, сборка `python3 build.py` → три площадки (решение пользователя 15.09.2026):
  - `docs/index.html` + `docs/audio/*.mp3` — **публичный сайт** (GitHub Pages публикует папку `docs/` ветки main):
    только бесплатные мок-тесты, без курса и без платного материала. Старый адрес `<siteUrl>demo/` оставлен как редирект на главную.
  - `lab-site/index.html` — **лаборатория**: тесты + курс + `src/data/paid/*.js`, `noindex`, свой ключ прогресса
    `kz-trainer:lab:v1`. В публичный git не входит. Живёт на `https://lab.qazaqtrainer.com` (воркер
    `qazaq-trainer-lab-site`, конфиг и скрипт — `tools/lab-deploy/`, деплой
    `npx wrangler deploy -c tools/lab-deploy/wrangler.jsonc`). Вход: логин и пароль в секретах воркера
    `LAB_USER`/`LAB_PASS` (`npx wrangler secret put ...`), в коде их нет; без секретов воркер не пускает никого.
    **`run_worker_first: true` в конфиге обязателен** — без него Cloudflare отдаёт статику мимо скрипта и пароль
    не спрашивается вовсе (поймано 15.09.2026: лаборатория открывалась всем). Сверху планируется Cloudflare Access
    по списку почт — он срабатывает до воркера, пароль остаётся вторым рубежом.
  - `dist/index.html` (всё одним файлом, открывать локально) и `dist/artifact.html` (Artifact той же ссылкой; аудио data-URI,
    потому что внешние файлы в артефакте запрещены). `dist/` не в git.
- Режим сборки виден приложению как `KZ.site.build` = `site` | `lab` | `inline`.
- **Посадочные страницы под поиск** (17.09.2026): приложение маршрутизирует через `#хэш`, поэтому для поисковика у сайта
  был один адрес. `build.py` генерирует статические страницы `docs/<lang>/<exam>/<level>/index.html` для `ru` и `kk`
  (по одной на каждую пару «экзамен × уровень», где есть готовые тесты) и кладёт их адреса в `sitemap.xml`.
  На странице: свой `<title>` и описание, `canonical`, `hreflang` ru/kk/x-default, og-теги, описание уровня, таблица
  разделов экзамена, список вариантов с их `summary` и кнопка `/#/test/<id>` внутрь приложения. Вёрстка своя и лёгкая
  (около 10 КБ), приложение туда не тянется. Тексты берутся **только** из данных (`focus`, `focus_kk`, `summary`,
  `summary_kk` и т. д.): если казахского поля нет, строка не выводится — ничего не переводим на ходу.
  Ссылки на эти страницы есть в самом низу главной (`/*SEONAV*/` в `src/index.html`, функция `seo_nav()`), иначе для
  поисковика они были бы страницами-сиротами; в сборки `lab` и `inline` блок не попадает.
  Метаданные экзаменов выгружает `node tools/dump_meta.js` (данные лежат в `.js` для браузера) в `tools/pages-meta.json`.
  **Этот кэш коммитится**: если `node` на машине нет, сборка берёт прошлый файл, если нет и его — страницы просто
  пропускаются с предупреждением, остальная сборка не ломается.

## Форматы (принципы, не менять без причины)
- Аудирование — скрипт озвучивается Web Speech API (kk-голос; есть в Microsoft Edge: Aigul/Daulet, нет в
  Chrome/Safari на macOS). Текст скрыт, вопросы видны, отвечать по ходу. Повтор прослушивания не ограничен, пока идёт время раздела
  (спецификация ҰТО: «Мәтін бірнеше рет тыңдалады»; QRT — видео в пределах 10 минут раздела; `sec.plays` задаёт лимит, если нужен).
  По истечении времени раздел закрывается сам (`timeUp()` в app.js): ответы фиксируются как есть, письмо/говорение переходят
  к самопроверке без возврата к тексту, показывается «Время вышло». Без голоса — запасной режим: текст показывается на `script.readSeconds`.
  Предзаписанные MP3: `tools/tts_azure.py` (Azure Speech, kk-KZ Aigul/Daulet, диалоги — чередование голосов,
  первый голос в `FIRST`; темп 0 % для всех уровней и паузы 350 мс — выбор пользователя по прослушиванию 06.09.2026,
  для синтеза тире внутри предложений и многоточия заменяются на запятые/точки (`for_speech`), текст на экране не меняется;
  пробные варианты: `--rate= --break= --suffix=-trial`), ключ только в `~/.config/qazaq-trainer/azure.env`. Выход `audio/<testId>.mp3`,
  `audio/manifest.json`; `KZ.audio` собирает build.py (сайт — файлы `docs/audio/`, артефакт — data-URI: 22 теста ≈ 14 МБ при лимите 16,
  новые тесты в артефакт только без аудио). В приложении `KZ.audio[testId]` имеет приоритет над TTS: кастомный плеер
  с паузой, но без перемотки, счёт прослушиваний по событию ended; в разборе — обычный `<audio controls>`.
- Интервью — запись с микрофона (MediaRecorder), хранится в IndexedDB `kz-trainer/recs`
  (кнопка записи не отключается по `featurePolicy` iframe — пробуем getUserMedia и объясняем отказ; в артефакте claude.ai
  микрофон может не пропускаться внутрь, тогда совет открыть отдельной вкладкой), ключ
  `<testId>/speaking/<qkey>`; в разборе показывается плеер. При «Пройти заново» записи раздела удаляются.
- Ответы скрыты до фиксации («Зафиксировать ответы»), потом разбор с объяснениями.
- Письмо: таймер + каркас тезис 2 / аргументы 9 / вывод 2 / проверка 2 мин + чек-лист.
- Интервью: комплекты по 3 вопроса, каркас ответа 15с / 75с / 15с, чек-лист.
- Формат заданий — рабочая реконструкция; это написано в интерфейсе, не убирать.
- Один визуальный стиль на всё; экзамен/уровень — бейдж, не смена дизайна.

## Внутренняя шкала подсчёта (акция «вернём деньги», решение пользователя 10.09.2026)
- `KZ.strict.pct` в exams.js: пороги на полуровень выше официальных ҚАЗТЕСТ (A1 35, A2 45, B1 55, B2 70, C1 90, C2 95 %).
  Вердикт `verdict(t)` в app.js считается **только по разделам с автоматической проверкой** (аудирование, чтение, лексика):
  все они пройдены и в каждом pct ≥ порога → «Ваш уровень по чтению и аудированию: X» (карточка «Результат» на странице теста,
  бейдж «✓ X» на хабе и странице экзамена; бейдж языконезависимый, потому что «уровень B1» в казахском — «B1 деңгейі»).
  Письмо и говорение показываются в списке с пометкой «самооценка, в вывод не входит» и на вердикт не влияют (решение 15.09.2026,
  стратегия запуска 1.2: обещать точность там, где оценку ставит себе сам сдающий, нельзя). **Пороги в интерфейсе не показываются

## Пилот «проверка письма командой», часть 4: данные, удаление, срок хранения (16.11.2026, та же ветка, не выложено)
- **Решения владельца** (не переспрашивать): работа, отчёт и привязка к чату хранятся **365 дней с отправки**, потом ночная очистка удаляет строку; человек может удалить свою работу сам в любой момент по коду

- **Удаление, сайт:** `POST /api/writing/delete` (`deleteWriting` в `tools/writing-api.js`, для посетителя, без ключа: код — право доступа), тело `text/plain` с `{code}` до 1 КБ. 200 `{deleted:true}`, 404 (кода нет или уже удалён), 400 (`bad_json` / `bad_code`), 413, GET → 405.
  Код нормализуется (дефисы, регистр). После удаления `status`, `report` и страница `/sheet/?c=…` отвечают «такого кода нет».
  В приложении: у каждой работы в «Мои работы на проверке» неброская ссылка «Удалить работу» (`.wr-link`), подтверждение в самой строке (`.wr-confirm`, фокус на «Отмена»; не `window.confirm`) → запрос → запись уходит из `state.writing`, из списка и из JSON экспорта на странице. 404 сервера тоже убирает запись; сбой сети или не-2xx — сообщение, запись остаётся.
- **Удаление, бот:** `/delete QT-XXXX-XXXX` (`wDelete` в `writing-bot.js`, разбор в `tgWebhook`): без кода — подсказка; кода нет или неверный — то же «не нашли», что у `/start w_…`; работа привязана к другому чату или ни к какому — отказ с советом удалить на сайте; свой чат — `DELETE … WHERE code AND chat`. Ответ двуязычный. Строка в `/help`, подсказка с командой в «Текст получен».
- **Срок хранения:** в `purge` (`tools/events-worker/worker.js`) константа `WRITING_KEEP_DAYS = 365`, удаляется `writing_submissions WHERE ts < now − 365 дней` **отдельным запросом** с `try/catch` (если миграция не применена, чистка событий не ломается). Работает только после деплоя воркера `events-worker`; воркер лаборатории чистку не ведёт (база общая).
- **Сброс прогресса:** если в прогрессе есть отправленные работы, «Сбросить весь прогресс» вместо `window.confirm` показывает свою панель (`#io-ask`): коды сотрутся с этого устройства, а работы останутся у нас на проверке; кнопки «Сначала удалить работы» (прокрутка к блоку `#wr-works`, `wrGoWorks`), «Всё равно сбросить», «Отмена». Работы на сервере сброс не удаляет. Без работ — прежний `confirm`.
  Импорт JSON и «Перенести сюда»: в части 7 коды работ при них не теряются (вливаются во входящий прогресс).
- **Страница privacy:** новый раздел «Проверка письма командой» (RU/KK), поправлены «У вас в браузере» (было «остаются только у вас»), «Что вы отправляете сами», «Зачем», «Сколько хранится», «Удаление и вопросы»; дата 16.11.2026. Раздел написан условно («если на сайте есть кнопка…»): пилот только в лаборатории, страница общая.

- **Не решено:** формулировка согласия и несовершеннолетние — вопрос юристу; обрабатывается ли текст внешними сервисами при подготовке отчёта (на странице этого нет); перенос прогресса/экспорт уносят и коды работ (а код открывает отчёт).

## Пилот «проверка письма командой», часть 6: карточки слов в листе (16.11.2026, та же ветка, не выложено)
- Человек нажимает на слово в своём тексте и видит маленькую карточку: в русской версии «основа — перевод» и часть речи, в казахской «основа — толкование», пример курсивом, часть речи. В спокойном состоянии текст выглядит как раньше (ни подчёркиваний, ни цвета; при наведении лёгкая подсветка, у нажатого слова жёлтая). Под текстом одна неброская строка: «Нажмите на любое слово, чтобы увидеть перевод» (в kk про толкование). Кнопок под словами нет. Карточку делает скрипт страницы (между метками `@sheet` в `src/sheet/index.html`, общий с шаблоном листа), записи слов ей даёт отчёт; казахских и русских строк в скрипте нет.
- **Данные в отчёте** (строит `build_sheet` в `qt_check.py`, только для листа с принятым словарём; без словаря отчёт прежний): слова текста автора, у которых есть запись, обёрнуты в `<span data-w="основа">`; у слова с ошибкой, которого нет в словаре (`ұлкен`), ещё `data-e="исправленное слово"` (карточка строится по исправленному, с пометкой «Написание исправлено: … → … (см. пометку N)»); у `<mark>` с исправлением `data-fw="основа основа …"` — основы слов исправления по порядку (`-` — без карточки), чтобы в режиме «с исправлениями» карточка показывала исправленное слово. Записи идут один раз, скрытым блоком `<div class="gl" aria-hidden="true">` внутри секции с текстом: `<div class="g" data-w="основа"><b>перевод / толкование</b><em>пример</em><i>часть речи</i></div>` (имя: `class="g nm"`, только слово и подпись «имя»), подписи `.k-fix`, `.k-see`. `.text` с карточками получает `role="group"`, `aria-label` и `tabindex="0"`, абзацы `lang="kk"`.
- **Список разрешённых тегов расширен только тремя атрибутами**: `data-w`, `data-e`, `data-fw` (теги и всё остальное прежнее: скрипты, обработчики, `style`, формы, фреймы, ссылки с `javascript:` отбрасываются как раньше). Значения читаются через `getAttribute` и сравниваются как строки; словарь на странице — объект без прототипа (`Object.create(null)`), поэтому основа `__proto__` или `constructor` безвредна; в карточку всё попадает через `textContent`, не как html. Проверено вручную испорченным отчётом: `onclick`, `<script>`, `<img onerror>` в записях и в словах ничего не выполняют, текст показывается как текст.
- **Поведение.** Нажатие открывает карточку под словом (над ним, если снизу нет места; в пределах экрана, на 375 px не вылезает и слово не перекрывает; проверено по всем словам образца). Закрывают: то же слово, нажатие мимо, Esc, смена языка и вида текста. Слова внутри пометок тоже открывают карточку, пара «пометка — замечание» подсвечивается, но страница не прокручивается к замечанию (перед глазами уже карточка; нажатие на номер или край пометки прокручивает как раньше). Слова без записи (стоп-список, слова без разбора) не нажимаются совсем. Выделение текста мышью карточку не открывает. В печать и PDF карточки, подсказка и скрытый блок не идут.
- **Клавиатура и скринридер.** Слова в порядок Tab не входят (`tabindex=-1`): блок текста — одна остановка Tab; на ней стрелки вправо/влево (и Enter, пробел для входа) ходят по словам, Home и End — первое и последнее, Enter или пробел — карточка, Esc — закрыть; пока карточка открыта, стрелки переносят её на соседнее слово. Пометки остаются отдельными остановками Tab, как раньше. Карточка для скринридера скрыта (`aria-hidden`), а её текст дублируется в невидимую область `role="status"` `aria-live="polite"`, поэтому читается при каждом открытии; слова в ней с `lang`.

## Пилот «проверка письма командой», часть 7: открытый приём, защита от спама, выход на основной сайт (17.11.2026, та же ветка, не выложено; владелец объявляет конкурс 23.11.2026)
- **Публичный воркер.** `tools/events-worker/worker.js` подключает `handleWriting` из `tools/writing-api.js` на `/api/writing/*` (функция `writing()`): посетителю `/submit`, `/status`, `/report` (GET), `/delete`; служебные `/list` и `/report` (POST) только с `X-Writing-Key` = `env.WRITING_KEY`
  (нет переменной — 403, как в лаборатории). CORS — те же источники `ALLOWED`, что у событий (qazaqtrainer.com, www, workers.dev, github.io; **лаборатории в списке нет и не должно быть**: события с её «Нового сайта» не должны попадать в статистику), чужой `Origin` → 403 до работы с базой, `OPTIONS` отвечает.
  Тела запросов посетителя — `text/plain`, предварительного запроса CORS нет (проверено в браузере: OPTIONS не приходит). Запрос без Origin (конвейер, curl) проходит, как у событий. Воркер лаборатории отвечает на свои пути как раньше, модуль и база общие.
  Для проверки на своём компьютере есть переменная `ALLOWED_EXTRA` (источники через запятую, только `--var`); на боевом воркере её нет и быть не должно.
- **Защита от спама, без IP, отпечатков и сторонних сервисов** (всё в `WR_LIMITS`, `tools/writing-api.js`, константы в одном месте):
  1) общий потолок приёма `rateHour: 40` в календарный час UTC и `rateDay: 300` в сутки UTC на всех вместе, ответ 429 `{error:'busy', retry}` + `Retry-After`; счётчики в таблице `writing_rate` (ключ `h<часы>` / `d<сутки>`, только число; **не** подсчёт строк, иначе «отправил и удалил» сбрасывал бы потолок), читаются до вставки и прибавляются после, отказы счётчик не раздувают, повтор того же текста (прежний код) потолок не тратит; потолок мягкий (при одновременных запросах превышение на единицы), окна календарные (на стыке часа может пройти до двух норм); старше 3 суток чистит ночной `purge`;
  2) поле-ловушка `hp` (скрытый `input.wr-hp` в блоке отправки, вне экрана, без Tab и скринридера): непусто → работа не сохраняется и не считается, а ответ обычный 200 с вымышленным кодом;
  3) время над заданием: клиент присылает секунды в `t` (время письма из прогресса `taskSec` или время с первого показа блока, что больше; ждать 20 с приходится только тому, кто вставил готовый текст и сразу нажал, остальные не ждут), сервер при `t` < 20 или без числа отвечает 400 `too_fast`; клиент сам не шлёт запрос раньше 20 с и пишет «Слишком быстро…», подсказка гаснет сама.
  Это барьер для простых ботов, не замок: `t` клиентский, прямой запрос с правдой в `t` проходит, держит его только потолок. **Для конкурса 40 работ в час может оказаться тесно, пересмотреть `rateHour`/`rateDay` и задеплоить воркер.** Страница privacy не менялась: ловушка и `t` не хранятся, счётчики числа без данных человека.
- **Сайт.** `writingReview: 'lab' | 'all' | false` в `src/data/site.js` (сейчас `'lab'`, включает владелец). `WR_ON` в app.js: `'all'` — сборки `lab` и `site` (если есть адрес: в лаборатории и её «Новом сайте» запросы на свой origin, на остальных — `eventsUrl`), `'lab'` — только `build === 'lab'`, `false` — нигде; `inline` (dist, артефакт) никогда. Хост `lab.*` определяется по `location.hostname`, поэтому «Новый сайт» внутри лаборатории не ходит на публичный воркер (его CORS бы не пустил).
